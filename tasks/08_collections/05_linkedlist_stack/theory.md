# Разбор задания

## Стек

Стек — структура «последним пришёл — первым вышел» (LIFO). Вершина — единственное место, где происходят операции:

| Операция | Смысл |
| --- | --- |
| `push(x)` | положить на вершину |
| `pop()` | снять с вершины |
| `peek()` | посмотреть на вершину |

## Deque

В Java нет отдельного класса `Stack`, который стоит использовать (старый `java.util.Stack` синхронизирован и считается устаревшим). Вместо него — интерфейс `Deque` («double-ended queue»), который умеет работать и как стек, и как очередь:

```java
Deque<Integer> stack = new LinkedList<>();
```

`Deque` — сокращение от double-ended queue. Методы `push`, `pop`, `peek` работают с головой.

## LinkedList

`LinkedList` — двусвязный список. Вставка и удаление с концов — O(1). Доступ по индексу — O(N), поэтому для частого `get(i)` лучше `ArrayList`. Для стека операции идут только с вершины, и `LinkedList` подходит.

## Пустой стек

`pop()` и `peek()` на пустом `Deque` выбрасывают `NoSuchElementException`. Чтобы не падать, проверяй `isEmpty()` или используй безопасные варианты `poll()`/`peekFirst()`, возвращающие `null`.

В задании требуется печатать `empty`, поэтому:

```java
if (stack.isEmpty()) {
    System.out.println("empty");
} else {
    System.out.println(stack.pop());
}
```

## Разбор команд

```java
String command = sc.next();
if (command.equals("push")) {
    stack.push(sc.nextInt());
} else if (command.equals("pop")) {
    ...
}
```

Сравнение строк — через `equals`, а не `==`.

## Частые ошибки

| Ошибка | Что происходит |
| --- | --- |
| `command == "push"` | Сравнение ссылок, работает непредсказуемо |
| `pop()` на пустом стеке | `NoSuchElementException` |
| Не прочитать аргумент после `push` | Следующая команда разбирается неверно |
| `add()`/`remove()` | Работают с другим концом; для стека нужны `push`/`pop` |
| `Stack<Integer>` | Устаревший класс, лучше `Deque` |
