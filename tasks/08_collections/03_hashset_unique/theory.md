# Разбор задания

## Set — множество

`Set` хранит **уникальные** элементы. Повторное добавление уже существующего значения игнорируется.

| Операция | Метод | В среднем |
| --- | --- | --- |
| Добавить | `add(x)` | O(1) |
| Проверить наличие | `contains(x)` | O(1) |
| Удалить | `remove(x)` | O(1) |
| Размер | `size()` | O(1) |

`add` возвращает `boolean`: `true`, если элемент действительно добавлен, и `false`, если такой уже был. Это иногда используют вместо `contains` + `add`.

## Порядок элементов

`HashSet` порядок **не гарантирует**. Чтобы вывести числа по возрастанию, копируем их в список и сортируем:

```java
List<Integer> sorted = new ArrayList<>(set);
Collections.sort(sorted);
```

Альтернатива — `TreeSet`, который всегда держит элементы отсортированными:

```java
Set<Integer> set = new TreeSet<>();
```

Для целых чисел `TreeSet` даёт тот же результат без ручной сортировки.

## Сложность

- `HashSet.add` — O(1) в среднем.
- Сортировка результата — O(M log M), где M — число уникальных.

## Автоупаковка

Как и в `ArrayList`, в `Set<Integer>` хранятся обёртки `Integer`. `add(5)` упаковывает `int`.

## Частые ошибки

| Ошибка | Что происходит |
| --- | --- |
| `Set<int>` | Нужна обёртка `Integer` |
| Полагаться на порядок `HashSet` | Тест сравнивает байты |
| `set.get(0)` | У `Set` нет доступа по индексу |
| `Collections.sort(set)` | Аргумент должен быть `List` |
| Считать, что `add` бросает исключение на повторе | Он просто возвращает `false` |
