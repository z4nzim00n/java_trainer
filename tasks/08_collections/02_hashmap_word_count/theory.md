# Разбор задания

## Что такое Map

`Map<K, V>` хранит пары «ключ → значение». По ключу можно быстро получить значение, положить новое или проверить наличие.

| Операция | Метод | В среднем |
| --- | --- | --- |
| Положить | `put(k, v)` | O(1) |
| Получить | `get(k)` | O(1) |
| Проверить ключ | `containsKey(k)` | O(1) |
| Удалить | `remove(k)` | O(1) |
| Все ключи | `keySet()` | O(N) |

В `HashMap` порядок ключей **не определён** и может меняться. Полагаться на него нельзя.

## Подсчёт частот

```java
counts.put(word, counts.getOrDefault(word, 0) + 1);
```

Разбор:

1. `getOrDefault(word, 0)` — если слово новое, берём `0`.
2. `+ 1` — увеличиваем счётчик.
3. `put` — записываем обратно.

Без `getOrDefault` пришлось бы писать:

```java
if (counts.containsKey(word)) {
    counts.put(word, counts.get(word) + 1);
} else {
    counts.put(word, 1);
}
```

## Сортировка ключей

```java
List<String> keys = new ArrayList<>(counts.keySet());
Collections.sort(keys);
```

`Collections.sort` для строк использует лексикографический порядок (`compareTo`). Для вывода в алфавитном порядке этого достаточно.

Альтернатива — `TreeMap`, который держит ключи отсортированными всегда:

```java
Map<String, Integer> counts = new TreeMap<>();
```

Тогда `keySet()` сразу в нужном порядке. Но `HashMap` + сортировка нагляднее показывает, что порядок нужно восстанавливать явно.

## Дженерики

```java
Map<String, Integer> counts = new HashMap<>();
```

Ключ — `String`, значение — `Integer` (обёртка, а не `int`).

## Частые ошибки

| Ошибка | Что происходит |
| --- | --- |
| `counts.get(word) + 1` без проверки | `NullPointerException` для нового слова |
| Полагаться на порядок `HashMap` | Тест сравнивает байты, порядок должен быть стабильным |
| `counts.put(word, 1)` в цикле | Счётчик всегда 1 |
| `Map<String, int>` | Дженерики не принимают примитивы |
| Забыть `Collections.sort` | Порядок вывода непредсказуем |
