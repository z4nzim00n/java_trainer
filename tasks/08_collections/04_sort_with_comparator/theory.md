# Разбор задания

## Comparator

`Comparator<T>` — объект, который описывает порядок сравнения двух элементов:

```java
int compare(T a, T b)
```

| Результат | Смысл |
| --- | --- |
| `< 0` | `a` раньше `b` |
| `0` | равны по порядку |
| `> 0` | `a` позже `b` |

## Составной порядок

Сначала сравниваем длину. Если она разная — её разность уже задаёт порядок. Если одинаковая — переходим к алфавиту:

```java
if (a.length() != b.length()) {
    return a.length() - b.length();
}
return a.compareTo(b);
```

`String.compareTo` возвращает лексикографическую разность. Использовать `a.length() - b.length()` безопасно: длины слов далеки от переполнения `int`.

## Лямбда-выражение

С Java 8 анонимный класс можно записать короче:

```java
Collections.sort(words, (a, b) -> {
    if (a.length() != b.length()) {
        return a.length() - b.length();
    }
    return a.compareTo(b);
});
```

Лямбда — это краткая запись функционального интерфейса (интерфейса с одним абстрактным методом). `Comparator` именно такой.

## Комбинаторы Java 8

Ещё короче:

```java
words.sort(Comparator.comparingInt(String::length).thenComparing(Comparator.naturalOrder()));
```

Выглядит компактно, но для первого знакомства анонимный класс нагляднее: видно, что именно сравнивается.

## Устойчивость

`Collections.sort` устойчив: элементы с равным ключом сохраняют исходный порядок. У нас при равной длине порядок задаётся явно, поэтому устойчивость не влияет на результат.

## Частые ошибки

| Ошибка | Что происходит |
| --- | --- |
| `return a.length() - b.length()` без второго условия | При равной длине порядок не определён |
| `return b.length() - a.length()` | Обратный порядок по длине |
| `compare` возвращает `boolean` | Неверная сигнатура, ошибка компиляции |
| `a - b` для строк | Строки нельзя вычитать |
| `Arrays.sort` для `List` | Нужен `Collections.sort` или `list.sort` |
