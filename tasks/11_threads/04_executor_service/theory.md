# Разбор задания

## Зачем пул потоков

Создавать новый `Thread` на каждую мелкую задачу дорого. `ExecutorService` переиспользует фиксированное число потоков:

```java
ExecutorService pool = Executors.newFixedThreadPool(2);
```

Задачи складываются в очередь и выполняются двумя рабочими потоками.

## Callable и Future

| | `Runnable` | `Callable<T>` |
| --- | --- | --- |
| Возвращает | ничего | значение типа `T` |
| Бросает | не может checked | может |

`submit` возвращает `Future<T>`:

```java
Future<Long> future = pool.submit(task);
Long value = future.get();   // ждёт и возвращает результат
```

`get()` объявляет `InterruptedException` и `ExecutionException` — второе заворачивает исключение из задачи.

## Сумма результатов

Порядок `futures` совпадает с порядком отправки. Поэтому сумма не зависит от того, в каком порядке задачи реально выполнялись.

## Завершение пула

```java
pool.shutdown();
```

`shutdown()` перестаёт принимать новые задачи и завершает уже отправленные. Без него программа может не завершиться: рабочие потоки пула — не демоны, JVM будет их ждать.

`shutdownNow()` дополнительно пытается прервать выполняющиеся задачи.

## try-with-resources

`ExecutorService` реализует `AutoCloseable` только с Java 19, поэтому в Java 8 используется явный `shutdown()`.

## Частые ошибки

| Ошибка | Что происходит |
| --- | --- |
| Забыть `shutdown()` | Программа может «висеть» |
| `future.get()` без обработки исключений | Ошибка компиляции |
| Сумма в `int` | Квадраты больших чисел переполняются |
| Создавать поток на каждое число | Дорого, теряется смысл пула |
| Читать результаты в порядке завершения | Сумма не изменится, но код сложнее |
