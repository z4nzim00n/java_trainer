# Разбор задания

## Индекс вместо значения

Если запомнить только значения `max` и `min`, непонятно, **где** их менять. Поэтому в цикле храним индексы:

```java
if (a[i] < a[minIndex]) minIndex = i;
```

После прохода `a[minIndex]` — первый минимальный элемент, `a[maxIndex]` — первый максимальный.

## Первый, а не последний

Строгое `<` обновляет индекс только при появлении **меньшего** значения. Равное значение не срабатывает, поэтому остаётся первый по порядку. Нестрогое `<=` дало бы последний.

## Обмен

```java
int tmp = a[minIndex];
a[minIndex] = a[maxIndex];
a[maxIndex] = tmp;
```

Порядок индексов не важен: если `minIndex > maxIndex`, обмен всё равно корректен.

## Когда индексы совпадают

Все элементы равны → `minIndex == maxIndex == 0`. Обмен `a[0]` с самим собой — три операции, результат не меняется. Код остаётся простым, без ветвления.

## Проверка на примере

`3 9 1 7 2`:

| Индекс | 0 | 1 | 2 | 3 | 4 |
| --- | --- | --- | --- | --- | --- |
| Значение | 3 | 9 | 1 | 7 | 2 |

`minIndex = 2` (значение 1), `maxIndex = 1` (значение 9). После обмена: `3 1 9 7 2`.

## Частые ошибки

| Ошибка | Что происходит |
| --- | --- |
| Хранить значения, а не индексы | Неизвестно, какие ячейки менять |
| `<=`/`>=` | Меняются последние минимум/максимум |
| Искать в двух отдельных циклах | Не ошибка, но два прохода вместо одного |
| Обмен без `tmp` | Значения затираются |
| Проверка `if (minIndex != maxIndex)` | Не обязательна, но и не вредит |
