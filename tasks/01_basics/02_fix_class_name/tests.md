# JAVA_01_02. Исправь имя класса и метод main — Тесты

## Компиляция

До исправления ошибок `Main.java` намеренно не компилируется — это ожидаемо. После исправления проверяй так:

```bash
javac -encoding UTF-8 Main.java
java Main
```

Для проверки эталона:

```bash
javac -encoding UTF-8 Solution.java
java Solution
```

Для проверки комментированной версии:

```bash
javac -encoding UTF-8 SolutionCommented.java
java SolutionCommented
```

> Это отдельные программы. Собирайте только один файл за раз.

## Проверка вывода

| Вход | Результат | Команда | Пояснение |
| --- | --- | --- | --- |
| 2 2 | `4\n` | `echo "2 2" \| java Main` | Обычный случай: произведение положительное |
| -4 4 | `-16\n` | `echo "-4 4" \| java Main` | Отрицательное число: знак минус сохраняется |
| 0 5 | `0\n` | `echo "0 5" \| java Main` | Умножение на ноль |

Во всех случаях в конце вывода ровно один перенос строки — его добавляет `println`.

## Крайние случаи

- **Числа с новой строки.** Ввод `2` и `2` на разных строках работает так же: `nextInt` пропускает любые пробельные символы, включая `\n`.
- **Лишние пробелы.** Ввод `  2   2  ` тоже работает: `nextInt` пропускает пробелы между числами.
- **EOF без `\n`.** Если последнее число не заканчивается переносом строки, `nextInt` всё равно его считает.
- **Пустой ввод.** Если чисел нет, программа упадёт с `NoSuchElementException` — по условию два числа подаются всегда.

## Автотесты

```bash
bash run_tests1_2.sh
```

Скрипт компилирует `Main.java` и сравнивает вывод с эталоном побайтово. Пока ошибки не исправлены, скрипт падает на этапе компиляции — это нормально.
