# Разбор задания

## parseInt

```java
int value = Integer.parseInt("42");   // 42
int bad = Integer.parseInt("abc");    // NumberFormatException
```

Метод принимает строку и возвращает `int`. Пробелы по краям он **не** игнорирует, поэтому перед вызовом полезен `trim()`.

## NumberFormatException

Непроверяемое исключение (наследник `RuntimeException`). Основные причины:

| Вход | Причина |
| --- | --- |
| `"abc"` | не число |
| `""` | пустая строка |
| `"3.14"` | `parseInt` не принимает дробную точку |
| `" 42 "` | пробелы, если не сделан `trim()` |
| `"99999999999"` | не помещается в `int` |

Для дробных чисел есть `Double.parseDouble`, для больших целых — `Long.parseLong`.

## Валидация на границе

Правило хорошего дизайна: проверяй внешние данные на входе (пользователь, файл, сеть) и дальше работай с уже корректными значениями. `try`/`catch` вокруг `parseInt` — типичный пример такой границы.

## Scanner.nextInt против parseInt

`sc.nextInt()` тоже бросает исключение при неверном вводе — `InputMismatchException`. Но с `nextLine` + `parseInt` проще вывести понятное сообщение и продолжить работу.

## Частые ошибки

| Ошибка | Что происходит |
| --- | --- |
| Нет `trim()` | Строка `" 42 "` считается неверной |
| `parseInt` без `catch` | Программа падает на `abc` |
| `Double.parseDouble` для целых | Принимает `3.14`, что противоречит условию |
| `catch (Exception e)` | Слишком широко |
| Проверять `line == "abc"` | Сравнение ссылок; и не покрывает все случаи |
