# Разбор задания

## Зачем finally

`finally` — блок, который выполняется **всегда**:

- если `try` завершился успешно;
- если исключение было поймано;
- если исключение не было поймано (перед пробрасыванием);
- даже если в `try` или `catch` стоит `return`.

```java
try {
    return 1;
} finally {
    System.out.println("finally");
}
```

Перед возвратом из метода `finally` всё равно выполнится.

## Типичное применение

Закрытие ресурсов: файлов, сетевых соединений, потоков. Ресурс должен быть освобождён независимо от того, чем закончилась работа.

```java
try {
    // работа с файлом
} finally {
    // закрыть файл
}
```

В современном Java для этого чаще используют try-with-resources:

```java
try (BufferedReader reader = Files.newBufferedReader(path)) {
    ...
}
```

Такая конструкция автоматически вызывает `close()`. Но `finally` по-прежнему нужен в общем случае.

## Порядок выполнения

```text
try → (catch при исключении) → finally
```

Если и `catch` выбросит исключение, `finally` всё равно выполнится.

## Опасность return в finally

`return` внутри `finally` перекрывает результат `try` и может «проглотить» исключение. Так писать почти никогда не нужно.

## Частые ошибки

| Ошибка | Что происходит |
| --- | --- |
| `Done` печатается в `try` | При исключении строка не выводится |
| `Done` в `catch` | При успехе строка не выводится |
| Нет `finally` | Один из двух сценариев теряет `Done` |
| `return` в `finally` | Перекрывает нормальное завершение |
| Пустой `catch` | Ошибка скрыта, но `finally` сработает |
