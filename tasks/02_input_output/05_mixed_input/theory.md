# Разбор задания

## Ловушка nextInt + nextLine

`Scanner` работает с потоком символов. `nextInt()` читает цифры числа и **останавливается перед** первым символом, который не является частью числа. Обычно это `\n`.

Что остаётся в потоке после `sc.nextInt()` при вводе `25\nAlice Smith\n`:

```text
\nAlice Smith\n
```

Следующий `nextLine()` читает всё до ближайшего `\n` — а он стоит сразу, поэтому возвращается **пустая строка**. Имя `Alice Smith` остаётся непрочитанным.

## Решение

Добавить «пустой» `nextLine()`, который заберёт оставшийся перевод строки:

```java
int age = sc.nextInt();
sc.nextLine();               // съедаем \n после числа
String name = sc.nextLine(); // читаем имя
```

Второй вариант — сразу прочитать строку и распарсить её:

```java
String first = sc.nextLine();
int age = Integer.parseInt(first.trim());
String name = sc.nextLine();
```

Но классический идиоматичный способ — лишний `nextLine()`.

## Почему это важно

Та же ловушка встречается в любом коде, где смешивают `nextInt`/`nextDouble` и `nextLine`. Даже опытные разработчики иногда на неё наступают. Запомни правило: **после чтения примитива через nextX() перед nextLine() нужен пустой nextLine()**.

## Порядок вывода

В задании: `<name>: <age>`. Конкатенация `name + ": " + age` даст именно это. `println` добавит `\n`.

## Частые ошибки

| Ошибка | Симптом |
| --- | --- |
| Нет `sc.nextLine()` после `nextInt()` | Вывод начинается с `: 25`, имя пустое |
| `sc.next()` вместо `nextLine()` для имени | Выводится только `Alice` |
| `println(name + ": " + age)` без пробела после `:` | `Alice:25` вместо `Alice: 25` |
