# Разбор задания

## Сколько раз вызывать nextInt

Каждый вызов `nextInt()` читает **ровно одно** число:

```java
int a = sc.nextInt();   // первое число
int b = sc.nextInt();   // второе число
```

Порядок важен: первый вызов съедает первое число, второй — второе.

## Разделители не важны

`Scanner` воспринимает любой whitespace как разделитель: пробел, табуляция, `\n`, `\r\n`.

```text
2 3        -> a=2, b=3
2\n3       -> a=2, b=3
2\t3       -> a=2, b=3
```

Поэтому один и тот же код работает и для ввода в одну строку, и для ввода в две строки.

## Арифметика

`a + b` — целочисленное сложение. Пока оба операнда `int`, результат `int`. Переполнение возможно, но в этой задаче числа маленькие.

## Частые ошибки

| Ошибка | Симптом |
| --- | --- |
| Один `nextInt()` на два числа | Второе число остаётся в потоке, сумма неверная или программа падает |
| `sc.nextInt(a)` | `int cannot be dereferenced` или несовместимая сигнатура: `nextInt` не принимает аргумент |
| Вывод через `print` | Нет завершающего `\n`, тест провален |
| Переменные `int a, b;` без инициализации и потом `a + b` | `variable a might not have been initialized` |

## Проверка на неверный ввод

В учебной задаче ввод гарантированно корректный. В реальном коде проверяют `sc.hasNextInt()` или ловят `InputMismatchException` — об этом в разделе про исключения.
