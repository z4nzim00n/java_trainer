# Разбор задания

## printf

`System.out.printf` — аналог C-шного `printf`. Первый аргумент — строка формата, дальше — значения:

```java
System.out.printf("Total: %.2f\n", price * count);
```

| Спецификатор | Что печатает |
| --- | --- |
| `%d` | Целое число |
| `%f` | Вещественное (по умолчанию 6 знаков) |
| `%.2f` | Вещественное с 2 знаками после точки |
| `%s` | Строка |
| `%n` | Перенос строки платформы |

Важно: `printf` **не добавляет** `\n` автоматически — его нужно указать в формате.

## Округление

`%.2f` округляет по правилам математики (half-up для типичных случаев):

```java
System.out.printf(Locale.US, "%.2f%n", 7.0);     // 7.00
System.out.printf(Locale.US, "%.2f%n", 0.30000000000000004); // 0.30
```

`0.1 * 3` в `double` равно `0.30000000000000004` из-за двоичного представления. На экране это незаметно, потому что `%.2f` округляет.

## Зачем Locale.US

`printf` использует локаль по умолчанию. На русской Windows это `ru_RU`, где разделитель дроби — запятая. Тогда вывод будет `Total: 7,00` и тест провалится. Явное `Locale.US` фиксирует точку независимо от системы.

То же касается `Scanner.nextDouble()`: без `useLocale(Locale.US)` он ждёт `3,5`, а не `3.5`.

## Частые ошибки

| Ошибка | Симптом |
| --- | --- |
| `System.out.printf("Total: %.2f", x)` | Нет перевода строки — тест провален |
| `%d` для `double` | `IllegalFormatConversionException` |
| Без `Locale.US` на русской системе | `7,00` вместо `7.00` |
| `printf("...")` без аргументов для `%.2f` | `MissingFormatArgumentException` |

## Сравнение с C

| C | Java |
| --- | --- |
| `printf("%.2f\n", x);` | `System.out.printf("%.2f\n", x);` |
| Локаль задаётся `setlocale` | Локаль передаётся явно: `printf(Locale.US, ...)` |
