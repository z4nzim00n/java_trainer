# Разбор задания

## next() и nextLine()

У `Scanner` есть два похожих метода, которые ведут себя по-разному:

| Метод | Что читает | Пример: вход `Hello world` |
| --- | --- | --- |
| `next()` | Одно «слово» до пробела | `Hello` |
| `nextLine()` | Всю строку до `\n` | `Hello world` |

В задаче нужна строка целиком, поэтому — `nextLine()`.

## Пробелы сохраняются

`nextLine()` не обрезает пробелы:

```text
"  spaced  " -> "  spaced  "
```

Если нужно убрать пробелы по краям, есть `String.trim()`, но в этой задаче этого делать **не** надо: вывод должен совпасть с вводом побайтово.

## Что если ввода нет

Если поток пуст (`< /dev/null`), `nextLine()` выбросит `NoSuchElementException`. В этой задаче тесты всегда подают хотя бы одну строку (возможно, пустую).

## Сравнение с C

| C | Java |
| --- | --- |
| `fgets(buf, size, stdin)` | `String line = sc.nextLine();` |
| `scanf("%s", word)` | `String word = sc.next();` |

В отличие от `fgets`, `nextLine()` не включает `\n` в результат.

## Частые ошибки

| Ошибка | Симптом |
| --- | --- |
| `sc.next()` вместо `nextLine()` | Выводится только первое слово |
| `println(sc.nextLine().trim())` | Пропадают начальные/конечные пробелы — тест провалится |
| `nextInt()` перед `nextLine()` | `nextLine()` вернёт пустую строку — разберём в задании 02_05 |
