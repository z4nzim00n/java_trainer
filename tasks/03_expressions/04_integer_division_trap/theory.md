# Разбор задания

## Как Java делит целые числа

Если оба операнда целые, оператор `/` выполняет **целочисленное деление**: результат округляется к нулю, дробная часть просто отбрасывается.

| Выражение | Результат | Почему |
| --- | --- | --- |
| `7 / 2` | `3` | `3.5` усекается до `3` |
| `-7 / 2` | `-3` | усечение идёт к нулю, а не к `-4` |
| `1 / 2` | `0` | дробная часть потеряна полностью |
| `7 / 2.0` | `3.5` | один операнд `double` — деление вещественное |

Именно поэтому `(a + b) / 2` в этой задаче для `a = 3`, `b = 4` даст `3`, а не `3.5`.

## Как получить вещественный результат

Есть два равноправных способа:

```java
double avg = (a + b) / 2.0;          // делим на double
double avg2 = (double) (a + b) / 2;  // приводим сумму к double
```

Важно, где стоит приведение. `(double) ((a + b) / 2)` **не поможет**: сначала выполнится целочисленное деление, а потом уже готовый `int` превратится в `double`. Приведение должно стоять до деления.

## Остаток от деления

Рядом с `/` живёт `%` — остаток:

```java
7 % 2   // 1
-7 % 2  // -1 (знак остатка совпадает со знаком делимого)
```

В задачах на цифры числа `% 10` даёт последнюю цифру, а `/ 10` отбрасывает её.

## Форматный вывод

```java
System.out.printf(Locale.US, "%.2f\n", avg);
```

| Элемент | Значение |
| --- | --- |
| `%f` | вещественное число |
| `.2` | ровно 2 знака после точки |
| `\n` | перенос строки |
| `Locale.US` | десятичная точка вместо запятой |

## Частые ошибки

| Ошибка | Что происходит |
| --- | --- |
| `(a + b) / 2` | Целочисленное деление: теряется `.5` |
| `(double) ((a + b) / 2)` | Приведение слишком позднее — дробь уже потеряна |
| `println(avg)` | Нет фиксированных двух знаков: `3.5`, а не `3.50` |
| Нет `\n` в конце | Тест не пройден |
| Нет `Locale.US` | На русской Windows вывод с запятой: `3,50` |
