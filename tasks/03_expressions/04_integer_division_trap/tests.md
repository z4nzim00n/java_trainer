# JAVA_03_04. Ловушка целочисленного деления — Тесты

## Компиляция

```bash
javac -encoding UTF-8 Main.java
java Main
```

Для эталона:

```bash
javac -encoding UTF-8 Solution.java
java Solution
```

Для комментированной версии:

```bash
javac -encoding UTF-8 SolutionCommented.java
java SolutionCommented
```

> Собирайте только один файл за раз: это три отдельные программы.

## Проверка вывода

| Вход | Результат | Пояснение |
| --- | --- | --- |
| `3 4` | `3.50\n` | (3 + 4) / 2 = 3.5 |
| `1 2` | `1.50\n` | (1 + 2) / 2 = 1.5 — с целыми было бы 1 |
| `-3 4` | `0.50\n` | (−3 + 4) / 2 = 0.5 |
| `5 5` | `5.00\n` | Формат `%.2f` печатает два знака даже у целого |

## Крайние случаи

- **Нечётная сумма** — именно здесь проявляется ловушка: `1 2` должно дать `1.50`, а не `1.00`.
- **Отрицательные числа** — работают как обычно; главное, чтобы деление было вещественным.
- **Сумма равна нулю** — например, `-5 5` даёт `0.00`.

## Как увидеть точные байты

```bash
echo "1 2" | java Main | od -An -t x1
```

Ожидаемые байты: `31 2e 35 30 0a` — это `1.50` и `\n`. Если вместо `2e` (точка) стоит `2c` (запятая), забыт `Locale.US`.
