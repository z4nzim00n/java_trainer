# JAVA_03_03. Обмен крайних цифр — Тесты

## Компиляция

Для проверки собственного решения:

```bash
javac -encoding UTF-8 Main.java
java Main
```

Для проверки эталона:

```bash
javac -encoding UTF-8 Solution.java
java Solution
```

Для проверки комментированной версии:

```bash
javac -encoding UTF-8 SolutionCommented.java
java SolutionCommented
```

> Это отдельные программы. Собирайте только один файл за раз.

## Проверка вывода

| Вход | Результат | Команда | Пояснение |
| --- | --- | --- | --- |
| `1234` | `4231\n` | `echo "1234" \| java Main` | 1 и 4 меняются местами: 4-23-1 |
| `1000` | `1\n` | `echo "1000" \| java Main` | 0-00-1 = 0001, ведущие нули у int отбрасываются |
| `9999` | `9999\n` | `echo "9999" \| java Main` | Все цифры одинаковы — число не меняется |
| `5678` | `8675\n` | `echo "5678" \| java Main` | 8-67-5 |

## Крайние случаи

- **Нулевая последняя цифра** (`1000`, `2000`, ...) — после обмена впереди оказываются нули, ответ печатается без них: `1`, `2`, ...
- **Все цифры одинаковы** (`9999`) — обмен ничего не меняет.
- **EOF без `\n`** — `printf '1234' | java Main` работает: `Scanner` не требует переноса после числа.
- **Отрицательные и нечетырёхзначные числа** — по условию не подаются, обрабатывать их не нужно.

## Как увидеть точные байты

```bash
echo "1000" | java Main | od -An -t x1
```

Ожидаемые байты: `31 0a` — это `1` и `\n` (`0a`). Если видишь `30 30 30 31` (`0001`), значит результат где-то превратился в строку с ведущими нулями.
