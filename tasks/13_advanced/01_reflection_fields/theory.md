# Разбор задания

## Что такое рефлексия

Рефлексия позволяет программе исследовать собственные классы во время выполнения: узнавать поля, методы, конструкторы, вызывать их и менять значения. Класс `Class` — точка входа.

```java
Class<?> type = Person.class;
```

То же самое можно получить через `person.getClass()` или `Class.forName("Person")`.

## Поля

| Метод | Что возвращает |
| --- | --- |
| `getFields()` | публичные поля, включая унаследованные |
| `getDeclaredFields()` | все поля, объявленные именно в этом классе, любого уровня доступа |
| `getField("name")` | одно публичное поле по имени |
| `getDeclaredField("name")` | одно объявленное поле по имени |

`Field` даёт доступ к имени (`getName()`), типу (`getType()`) и значению (`get()` / `set()`).

## Тип поля

`field.getType()` возвращает `Class<?>`. Для `int` это `int.class`, для `String` — `String.class`. Короткое имя типа печатает `getSimpleName()`:

```java
field.getType().getSimpleName()   // "int", "String"
field.getType().getName()         // "int", "java.lang.String"
```

Именно поэтому в ожидаемом выводе `int`, а не `java.lang.Integer`: примитивы не имеют пакета.

## Порядок полей

Спецификация Java не гарантирует порядок, в котором `getDeclaredFields()` вернёт поля. В разных JVM и версиях он может отличаться. Поэтому результат сортируют по имени — так вывод детерминирован и тест стабилен.

## Зачем это нужно

Рефлексию используют фреймворки: Spring ищет аннотации на полях, JUnit находит методы `@Test`, Jackson сериализует объекты по полям. Понимание рефлексии объясняет, как «магия» библиотек работает под капотом.

## Частые ошибки

| Ошибка | Что происходит |
| --- | --- |
| `getFields()` вместо `getDeclaredFields()` | Приватные поля не попадают в вывод |
| Нет сортировки | Порядок строк непредсказуем, тест нестабилен |
| `getName()` вместо `getSimpleName()` | `java.lang.String` вместо `String` |
| Путаница имени поля и типа | Строки вида `String: age` |
