# Разбор задания

## Нейтральный элемент умножения

Сумму накапливают с `0`, произведение — с `1`:

```text
0 + x = x
1 * x = x
```

Если начать произведение с нуля, оно навсегда останется нулём.

## Проблема «нечего умножать»

Если в числе нет нечётных цифр (например, `2468`), цикл ничего не умножит, и `product` останется `1`. Но по условию ответ должен быть `0`. Значит, нужно отдельно запомнить, встретилась ли хотя бы одна нечётная цифра — для этого служит `boolean`-флаг:

```java
boolean found = false;
...
    found = true;
...
System.out.println(found ? product : 0);
```

`found ? product : 0` — тернарный оператор: если `found` истинно, берётся `product`, иначе `0`.

## Почему long

Максимум для `int` — около `2.1 * 10^9`. Произведение десяти цифр `9` равно `3 486 784 401` — это уже больше `int`. `long` вмещает до `9.2 * 10^18`, чего с запасом хватает.

Заметь: при умножении `product *= digit`, где `product` — `long`, а `digit` — `int`, результат автоматически приводится к `long`. Переполнения не будет.

## Чётность

`digit % 2 == 1` — нечётная. Можно писать `digit % 2 != 0`, это то же самое для неотрицательных цифр. Ноль чётный и в произведение не попадает.

## Частые ошибки

| Ошибка | Что происходит |
| --- | --- |
| `product = 0` | Произведение всегда `0` |
| Нет флага | Для `2468` печатается `1` вместо `0` |
| `digit % 2 == 0` | Перемножаются чётные цифры |
| `int product` | Возможно переполнение на длинных числах |
| Забыть `n /= 10` | Бесконечный цикл |
