# Разбор задания

## Сборка числа из цифр

Две операции:

| Операция | Смысл |
| --- | --- |
| `x * 10` | сдвинуть все цифры влево, освободив место справа |
| `x * 10 + d` | приписать цифру `d` справа |

Пример для `n = 123`:

```text
шаг 1: reversed = 0 * 10 + 3 = 3
шаг 2: reversed = 3 * 10 + 2 = 32
шаг 3: reversed = 32 * 10 + 1 = 321
```

## Куда деваются нули

Если последняя цифра исходного числа — `0`, она добавляется справа как `0 * 10 + 0`, то есть значение не меняется. Но когда число `12340` разворачивается, ноль из конца становится ведущим: `0 4 3 2 1`. Как только появляется первая ненулевая цифра, ведущие нули перестают влиять на значение. Именно поэтому строковый реверс с `"12340" -> "04321"` дал бы лишний ноль, а арифметический — нет.

## Почему long

Максимальное число в условии — `2 000 000 000`, его разворот `0 000 000 002` = `2` — мало. Но если бы подали, например, `1 234 567 899`, разворот `9 987 654 321` уже не влезает в `int` (максимум `2 147 483 647`). `long` снимает вопрос.

При этом само входное число читается как `int` — оно гарантированно помещается. `reversed` объявлен `long`, поэтому `reversed * 10` вычисляется в `long`.

## Ноль

Для `n = 0` цикл не выполняется, `reversed` остаётся `0`. Ответ — `0`, и это единственный случай, когда ноль не является ведущим.

## Частые ошибки

| Ошибка | Что происходит |
| --- | --- |
| `reversed = n % 10` | Берётся только последняя цифра |
| Нет `* 10` | Цифры складываются, а не собираются в число |
| `int reversed` | Возможно переполнение |
| Преобразование в строку и реверс | Появляются ведущие нули: `04321` |
| Забыть `n /= 10` | Бесконечный цикл |
