# Разбор задания

## Как «разобрать» число на цифры

Десятичная запись числа устроена так: последняя цифра — это остаток от деления на 10, всё остальное — результат целочисленного деления на 10.

```text
12345 % 10 = 5      12345 / 10 = 1234
1234  % 10 = 4      1234  / 10 = 123
123   % 10 = 3      123   / 10 = 12
12    % 10 = 2      12    / 10 = 1
1     % 10 = 1      1     / 10 = 0
```

Сумма: 5 + 4 + 3 + 2 + 1 = 15.

## Цикл while

```java
while (условие) {
    // тело
}
```

Проверяет условие **до** каждой итерации. Здесь условие `n > 0`: как только число станет `0`, цикл закончится.

Можно было бы записать и через `for (; n > 0; n /= 10)`, но `while` читается естественнее: мы не знаем заранее, сколько цифр в числе.

## Что с нулём

Для `n = 0` условие `0 > 0` ложно с самого начала, тело не выполняется, `sum` остаётся `0`. Это ровно то, что нужно: сумма цифр нуля — ноль.

Если бы использовался цикл `do { ... } while (n > 0)`, тело выполнилось бы один раз и дало бы `0 % 10 = 0` — для нуля тоже корректно, но для этой задачи `while` проще.

## int или long

`n` помещается в `int`, а сумма цифр числа до 2 миллиардов — максимум `9 * 10 = 90`, тоже `int`. Переполнения нет.

## Частые ошибки

| Ошибка | Что происходит |
| --- | --- |
| Забыть `n /= 10` | Бесконечный цикл |
| `n % 10` без `n /= 10` | Бесконечно добавляется последняя цифра |
| `while (n >= 0)` | Тоже бесконечный цикл: ноль никогда не станет меньше нуля |
| Работать с `String` и `charAt` | Не ошибка, но здесь цикл с арифметикой проще |
| `sum = n % 10` вместо `+=` | Считается только последняя цифра |
