# Разбор задания

## Цикл for

```java
for (int i = 0; i < n; i++) {
    // тело цикла
}
```

Три части в скобках: инициализация (`int i = 0`), условие продолжения (`i < n`), шаг (`i++`). В Java переменную `i` можно объявить прямо в заголовке цикла — её область видимости ограничена циклом.

## Как искать максимум

Классический алгоритм:

1. Взять первый элемент как текущий максимум.
2. Пройти по остальным элементам.
3. Если очередной элемент больше максимума — запомнить его.

```java
int max = sc.nextInt();          // первый элемент
for (int i = 1; i < n; i++) {
    int value = sc.nextInt();    // очередной элемент
    if (value > max) {
        max = value;
    }
}
```

## Почему не max = 0

Если инициализировать максимум нулём, то для последовательности `-5 -2 -9` ответом станет `0`, хотя такого числа во входе не было. Первый элемент — единственное значение, которое гарантированно существует.

Альтернатива — `Integer.MIN_VALUE`, минимально возможный `int`, но вариант с первым элементом понятнее и не требует помнить константу.

## Строгое или нестрогое сравнение

`value > max` и `value >= max` для поиска **значения** максимума дают одинаковый ответ. Разница важна, когда ищут индекс: `>` оставит первый из равных максимумов, `>=` — последний.

## Чтение чисел

`Scanner.nextInt()` сам пропускает пробелы и переносы строк, поэтому формат ввода (в одну строку или в столбик) не важен.

## Частые ошибки

| Ошибка | Что происходит |
| --- | --- |
| `max = 0` | Неверно для полностью отрицательной последовательности |
| `for (i = 1; i <= n; i++)` | Лишняя итерация и `NoSuchElementException` на конце |
| Сравнение `value < max` | Ищется минимум, а не максимум |
| Не считать первое число отдельно | Потеря первого элемента или лишнее чтение |
