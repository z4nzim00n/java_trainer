# Разбор задания

## Побитовое XOR

`^` — побитовое «исключающее ИЛИ». Для каждого бита результат равен `1`, если биты операндов различаются:

```text
  1010
^ 0110
------
  1100
```

## Три свойства, которые решают задачу

| Свойство | Пример |
| --- | --- |
| `x ^ x = 0` | `5 ^ 5 = 0` |
| `x ^ 0 = x` | `5 ^ 0 = 5` |
| Коммутативность | `a ^ b ^ c = c ^ a ^ b` |

Из них следует ассоциативность: `(a ^ b) ^ c = a ^ (b ^ c)`. Поэтому можно накапливать XOR в одной переменной, не заботясь о порядке.

## Почему это работает

Пусть числа: `1 2 3 2 1`. Накопим XOR:

```text
0 ^ 1 = 1
1 ^ 2 = 3
3 ^ 3 = 0
0 ^ 2 = 2
2 ^ 1 = 3
```

Каждая пара одинаковых чисел где-то по пути даёт `0`, и в итоге остаётся `3` — непарное число.

## Сложность

- Время: O(N) — один проход.
- Память: O(1) — одна переменная `int`.

Альтернативы (массив с подсчётом частот или `HashMap`) требуют O(N) памяти. XOR — самый элегантный вариант, и именно его ждут в Школе 21.

## Отрицательные числа

XOR работает с двоичным представлением `int`, включая отрицательные числа в дополнительном коде. Свойства `x ^ x = 0` и `x ^ 0 = x` сохраняются, поэтому `-7` находится корректно.

## Частые ошибки

| Ошибка | Что происходит |
| --- | --- |
| `result += value` | Сумма, а не XOR: пары не гасятся |
| `result = result ^ i` | Используется индекс цикла, а не значение |
| `result *= value` | Произведение, неверный результат |
| Сортировка и поиск пары | Работает, но сложнее и медленнее |
