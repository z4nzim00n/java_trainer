# Разбор задания

## char и его код

`char` — числовой тип. Символ `'a'` хранится как код 97, `'A'` — как 65, `'z'` — 122. Арифметика с `char` разрешена, но результат выражения имеет тип `int`, поэтому нужно обратное приведение:

```java
char next = (char) ('a' + 1);   // 'b'
```

## Сдвиг внутри диапазона

1. `c - 'a'` — позиция буквы в алфавите (0 для `a`, 25 для `z`).
2. `+ k` — сдвиг.
3. `% 26` — заворот: 25 + 3 = 28, 28 % 26 = 2 → `c`.
4. `'a' + ...` — обратно к коду символа.
5. `(char)` — приведение `int` к `char`.

Для заглавных букв та же схема с базой `'A'`.

## Почему нельзя просто c + k

`'z' + 1` даёт код 123 — это `{`, а не `a`. Модуль по 26 обеспечивает заворот. Кроме того, `c + k` имеет тип `int`, и без приведения к `char` строку не собрать.

## nextInt + nextLine

`nextInt()` читает только число и не забирает перевод строки после него. Следующий `nextLine()` вернул бы пустую строку. Поэтому:

```java
int k = sc.nextInt();
sc.nextLine();          // съедаем остаток первой строки
String text = sc.nextLine();  // теперь читаем настоящий текст
```

Это классическая ловушка `Scanner`.

## Остальные символы

Условия `c >= 'a' && c <= 'z'` и `c >= 'A' && c <= 'Z'` отбирают только латинские буквы. Всё остальное (`' '`, `','`, `'!'`, цифры) копируется как есть — это важно для формата `Hello, World!`.

## Частые ошибки

| Ошибка | Что происходит |
| --- | --- |
| Нет `% 26` | `z` превращается в `{` |
| Нет приведения `(char)` | Ошибка компиляции при `append` |
| Забыть `sc.nextLine()` после `nextInt` | Текст читается пустым |
| Сдвигать все символы подряд | Знаки и цифры ломаются |
| Перепутать базы `'a'` и `'A'` | Заглавные буквы сдвигаются неверно |
| `k` без нормализации (если k > 25) | Здесь гарантировано `0..25`, но `((k % 26) + 26) % 26` — универсальнее |
