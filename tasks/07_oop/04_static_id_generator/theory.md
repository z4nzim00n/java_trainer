# Разбор задания

## Поле экземпляра против статического поля

| | Поле экземпляра | Статическое поле |
| --- | --- | --- |
| Принадлежит | конкретному объекту | классу целиком |
| Копий | по одной на каждый `new` | одна на программу |
| Доступ | `obj.field` | `User.field` (или через объект, но так не пишут) |

```java
class User {
    private static int nextId = 1;   // одна переменная на всех
    private int id;                  // своя у каждого пользователя
}
```

## Что делает nextId++

`id = nextId++;` — постфиксный инкремент: сначала `id` получает текущее значение `nextId`, потом `nextId` увеличивается на 1. Первый пользователь получает `1`, счётчик становится `2`, и так далее.

Если написать `id = ++nextId;`, первый пользователь получил бы `2` — префиксный инкремент сначала увеличивает.

## Статический счётчик и JVM

Значение `static`-поля живёт, пока жив класс в запущенной JVM. При каждом новом запуске программы оно снова равно `1`. Внутри одного запуска все объекты делят одно значение.

## Статические методы

`static`-метод не имеет доступа к `this` и к полям экземпляра:

```java
static int getNextId() { return nextId; }   // можно
static String getName() { return name; }    // нельзя, name — поле объекта
```

## Частые ошибки

| Ошибка | Что происходит |
| --- | --- |
| `private int nextId = 1;` | У каждого объекта свой счётчик, все получают `1` |
| `id = ++nextId;` | Нумерация начинается с 2 |
| `this.nextId` в статическом контексте | Ошибка компиляции |
| Инициализировать `nextId` в конструкторе | Счётчик сбрасывается на каждом `new` |
| Сделать `id` статическим | Все объекты «показывают» один и тот же id |
