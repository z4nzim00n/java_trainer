# Разбор задания

## Инкапсуляция: прячем поля, открываем методы

В прошлом задании поля `Rectangle` были открыты: любой код мог записать `rect.width = -5`. Для прямоугольника это терпимо, а для банковского баланса — нет: отрицательный баланс недопустим по бизнес-правилам.

**Инкапсуляция** — принцип ООП: данные объекта скрыты внутри класса, а доступ к ним идёт через методы, которые класс контролирует.

```java
class User {
    private int balance;          // скрыто от всех снаружи

    int getBalance() {            // геттер — чтение
        return balance;
    }

    void setBalance(int balance) { // сеттер — запись с проверкой
        if (balance >= 0) {
            this.balance = balance;
        }
    }
}
```

| Модификатор | Кто имеет доступ |
| --- | --- |
| `private` | Только код внутри этого же класса |
| (без модификатора, package-private) | Классы того же пакета |
| `public` | Все |

Если из `Main` написать `user.balance = -100`, компилятор выдаст ошибку: *balance has private access in User*. Единственный путь изменить баланс — сеттер, а он проверяет значение.

## Геттеры и сеттеры — соглашения

| Метод | Имя | Что делает |
| --- | --- | --- |
| Геттер поля `name` | `getName()` | Возвращает значение поля |
| Геттер поля `balance` | `getBalance()` | Возвращает значение поля |
| Сеттер поля `balance` | `setBalance(int balance)` | Устанавливает значение (с проверкой) |

Имена придуманы не случайно: это JavaBeans-соглашение, его ждут библиотеки и фреймворки. Геттер для `boolean` часто называют `isXxx()`.

## this: поле или параметр?

В сеттере параметр называется так же, как поле:

```java
void setBalance(int balance) {
    this.balance = balance;   // this.balance — поле, balance — параметр
}
```

`this` — ссылка на текущий объект. Без `this` строка `balance = balance` присвоила бы параметр самому себе, а поле осталось бы прежним. Компилятор не предупредит — это классическая тихая ошибка.

## Конструктор

```java
User(String name, int balance) {
    this.name = name;
    this.balance = balance;
}
```

Конструктор вызывается при `new User("Alice", 100)` и заполняет поля. Имя конструктора совпадает с именем класса, тип возврата не указывается (даже `void` нельзя).

## Частые ошибки

| Ошибка | Что происходит |
| --- | --- |
| `balance = balance;` в сеттере без `this` | Параметр присваивается сам себе, поле не меняется |
| Проверка только в `main`, сеттер без защиты | Любой другой вызов сеттера может записать отрицательный баланс |
| `public int balance` | Поле открыто — инкапсуляции нет, проверку можно обойти |
| Геттер `void getName()` | Геттер обязан возвращать значение, `void` — ошибка компиляции |
| `System.out.println("Некорректный баланс")` | Русский вывод ломается на Windows — только ASCII (`Invalid balance`) |
| Забыл `\n` (использовал `print`) | Строки склеиваются, тест не проходит |
