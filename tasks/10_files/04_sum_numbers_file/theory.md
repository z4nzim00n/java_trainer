# Разбор задания

## Scanner поверх файла

```java
Scanner file = new Scanner(Paths.get(path), "UTF-8");
```

Конструктор `Scanner(Path, String)` принимает путь и имя кодировки. Он объявляет `throws IOException` — это checked-исключение.

## hasNextInt

```java
while (file.hasNextInt()) {
    sum += file.nextInt();
}
```

Проверяем, начинается ли следующий токен с числа. Если файл заканчивается или встречается нечисловой токен, цикл останавливается.

Пара `hasNextInt`/`nextInt` — аналог `hasNext`/`next` для целых.

## Сумма и тип

`sum` удобно объявить `long`: сумма большого количества `int` может переполнить `int`. В наших тестах хватило бы и `int`, но `long` — безопасная привычка.

## Альтернативы

| Способ | Особенность |
| --- | --- |
| `Scanner` | простой, токенизирует сам |
| `Files.readAllLines` + `split` | больше кода |
| `BufferedReader` + `split` | быстрее, больше контроля |
| `Files.lines` (Java 8) | поток строк, функциональный стиль |

## Закрытие ресурса

`Scanner` поверх файла держит открытый дескриптор. В хорошем коде его закрывают:

```java
try (Scanner file = new Scanner(Paths.get(path), "UTF-8")) {
    ...
}
```

try-with-resources автоматически вызовет `close()`. В простой учебной программе можно не закрывать — JVM завершится и освободит ресурсы, но привычка полезна.

## Частые ошибки

| Ошибка | Что происходит |
| --- | --- |
| `while (file.hasNext())` + `nextInt()` | `InputMismatchException` на нечисловом токене |
| Нет `hasNextInt` | Неизвестно, когда остановиться |
| `new Scanner(path)` со строкой вместо `Path` | Конструктора нет |
| Сумма в `int` | Возможно переполнение |
| Забыть кодировку | Платформенно-зависимое поведение |
