# Разбор задания

## Аргументы main

`public static void main(String[] args)` получает массив аргументов командной строки:

```bash
java Main /tmp/data.txt
```

Тогда `args[0]` равно `"/tmp/data.txt"`. Если аргументов нет, обращение к `args[0]` бросит `ArrayIndexOutOfBoundsException` — в реальном коде стоит проверять `args.length`.

## Путь к файлу

`Paths.get("...")` превращает строку в объект `Path`. Он поддерживает и относительные, и абсолютные пути.

## Чтение всего файла

```java
byte[] data = Files.readAllBytes(path);
```

Метод из `java.nio.file.Files` (Java 7+) читает файл целиком. Для небольших файлов это самый простой способ. Для больших используют потоки (`BufferedReader`, `Files.lines`), чтобы не держать всё в памяти.

## Кодировка

Байты сами по себе не текст. Чтобы получить строку, нужно знать кодировку:

```java
new String(data, StandardCharsets.UTF_8)
```

`StandardCharsets.UTF_8` — явная и безопасная кодировка. Без указания используется системная, что делает поведение платформенно-зависимым.

## print против println

| Метод | Что делает |
| --- | --- |
| `print` | выводит ровно переданное |
| `println` | добавляет `\n` в конце |

Если файл заканчивается переводом строки, `println` добавит ещё один — байты не совпадут.

## Обработка ошибок

`readAllBytes` объявляет `throws IOException` — это checked-исключение. Метод `main` может либо объявить `throws IOException`, либо обработать его через `try`/`catch`. Для понятного сообщения лучше второй вариант:

```java
try {
    ...
} catch (IOException e) {
    System.out.println("Error: file not found");
}
```

## Частые ошибки

| Ошибка | Что происходит |
| --- | --- |
| `println` вместо `print` | Лишний `\n` в конце |
| Нет кодировки | Зависит от системы, кириллица может сломаться |
| `args[0]` без проверки | Падение при запуске без аргументов |
| `new File(args[0]).read()` | Такого метода нет |
| Игнорирование `IOException` | Ошибка компиляции для checked-исключения |
