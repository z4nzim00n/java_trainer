# Разбор задания

## Что такое сигнатура

Многие форматы начинаются с фиксированных байтов — «магических чисел». По ним тип определяется надёжнее, чем по расширению: файл `photo.jpg` может на самом деле быть PDF.

| Формат | Сигнатура | ASCII |
| --- | --- | --- |
| PNG | `89 50 4E 47` | `\x89PNG` |
| PDF | `25 50 44 46` | `%PDF` |
| ZIP | `50 4B 03 04` | `PK..` |
| JPEG | `FF D8 FF` | — |
| GIF | `47 49 46 38` | `GIF8` |

## byte знаковый

В Java `byte` — от −128 до 127. Байт `0x89` (137) не помещается в положительный диапазон и хранится как −119. Сравнение `data[0] == 0x89` не скомпилируется как ожидается: `0x89` — это `int` 137, а `data[0]` повышается до `int` −119.

Решение:

```java
(data[0] & 0xFF) == 0x89
```

`& 0xFF` оставляет только младшие 8 бит и превращает −119 в 137.

Для ASCII-байтов (`'P'`, `'N'`, `'G'`) отрицательных значений нет, поэтому можно сравнивать напрямую.

## Порядок проверок

Проверки идут цепочкой `if / else if`. PNG, PDF и ZIP имеют разные первые байты, поэтому порядок не важен. Важна проверка длины: у короткого файла обращение к `data[3]` бросит `ArrayIndexOutOfBoundsException`.

## Файлы в Java

`Files.readAllBytes` возвращает `byte[]`. Для больших файлов читают только первые несколько байтов через `InputStream`, но для учебной задачи достаточно целиком.

## Частые ошибки

| Ошибка | Что происходит |
| --- | --- |
| `data[0] == 0x89` | Сравнение −119 и 137, всегда `false` |
| Нет проверки длины | Исключение на коротком файле |
| `data[0] == 'P'` для PNG | Первый байт PNG — `0x89`, а не `P` |
| Сравнивать расширение | Ненадёжно |
| `data.length()` | У массива поле `length` |
