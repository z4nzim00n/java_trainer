# Разбор задания

## Чтение stdin до конца

`Scanner.hasNextLine()` возвращает `false`, когда поток закончился. Цикл

```java
while (sc.hasNextLine()) {
    sb.append(sc.nextLine());
    if (sc.hasNextLine()) sb.append('\n');
}
```

собирает все строки, вставляя `\n` **между** ними. В конце лишнего перевода нет.

## Запись файла

```java
byte[] data = text.getBytes(StandardCharsets.UTF_8);
Files.write(Paths.get(args[0]), data);
```

`Files.write` создаёт файл (или перезаписывает существующий) и записывает массив байтов. Кодировка снова указывается явно.

## Длина в байтах, а не символах

`data.length` — число байтов. Для ASCII оно совпадает с числом символов. Для кириллицы в UTF-8 каждая буква занимает 2 байта, поэтому `"Привет"` — это 12 байтов, а не 6 символов. В задании печатается именно размер массива байтов.

## Проверка результата

Файл можно посмотреть:

```bash
cat /tmp/out.txt
od -An -t x1 /tmp/out.txt
```

`saved: N bytes` — хороший способ убедиться, что записалось ровно то, что ожидалось.

## IOException

`Files.write` объявляет `throws IOException`. Обрабатываем его так же, как при чтении, и выводим сообщение об ошибке.

## Частые ошибки

| Ошибка | Что происходит |
| --- | --- |
| `sb.append('\n')` после каждой строки | Лишний перевод в конце |
| `getBytes()` без кодировки | Платформенно-зависимый результат |
| `data.length()` | У массива поле `length`, без скобок |
| Считать `length` в символах | Для кириллицы число не совпадёт |
| Не обработать `IOException` | Ошибка компиляции |
