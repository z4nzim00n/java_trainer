# Формат задания Java-тренажёра

Этот документ описывает, как устроено каждое задание. Образец — папка
`tasks/01_basics/01_hello_world/` (прочитай все её файлы перед созданием заданий).

## Файлы задания (7 штук)

Каждая папка задания `tasks/<раздел>/<NN_имя>/` содержит:

| Файл | Назначение |
| --- | --- |
| `README.md` | Условие: табка с метаданными, текст задания, примеры ввода/вывода |
| `Main.java` | Стартовый файл для ученика. `public class Main`. Для задач «напиши с нуля» — компилируемый скелет с `// TODO`. Для задач «исправь ошибки» — код с намеренными ошибками (НЕ компилируется) |
| `Solution.java` | Эталонное решение. `public class Solution` |
| `SolutionCommented.java` | То же решение с обучающими комментариями. `public class SolutionCommented` |
| `theory.md` | Разбор: объяснение темы для новичка, таблицы, частые ошибки |
| `tests.md` | Ручная проверка: команды компиляции/запуска, таблица тест-кейсов, крайние случаи |
| `run_testsN_M.sh` | Автотест. `N` — номер раздела, `M` — номер задания (например `run_tests3_2.sh`) |

## Жёсткие правила

1. **Java 8.** Никаких `var`, `List.of`, `String.repeat`, `Stream.toList`, records, switch-expressions. Только синтаксис и API Java 8. Компиляция идёт с `--release 8 -Werror`.
2. **Один файл — один публичный класс.** Все вспомогательные классы в том же файле — package-private (без `public`). Имя публичного класса = имя файла.
3. **Вывод программы — только ASCII.** Никаких русских строк в `System.out` (на Windows другая кодировка). Сообщения вроде `true`, `false`, `IllegalArgument`, `n/a`, `OK`, `ERROR`. Русские комментарии в коде — можно (компиляция с `-encoding UTF-8`).
4. **Точный вывод.** Тесты сравнивают побайтово (с нормализацией `\r\n`→`\n`). В README явно указано, есть ли перенос строки в конце. `println` = с `\n`, `print` = без.
5. **Никаких комментариев в `Solution.java`** (как в Школе 21). Комментарии только в `SolutionCommented.java` и в стартовых `Main.java` (TODO).
6. **Стиль:** 4 пробела, фигурные скобки в конце строки (K&R), как в образце.
7. **Locale.US для дробных чисел.** На русской Windows `Scanner.nextDouble()` и `printf("%f")` используют запятую. Чтобы тесты с точкой (`3.5`) работали везде: `Scanner sc = new Scanner(System.in); sc.useLocale(Locale.US);` (импорт `java.util.Locale`) и `System.out.printf(Locale.US, "%.2f", x)`. Целые числа (`nextInt`) локали не зависят.

## run_testsN_M.sh — шаблон

```bash
#!/usr/bin/env bash
set -e
cd "$(dirname "$0")"
source ../../../scripts/lib.sh

compile

run_case "2 2" $'4\n'
run_case "-4 4" $'-16\n'
run_case_devnull $'0\n'

if [ -z "$FAILED" ]; then
  echo "Все тесты пройдены"
else
  echo "Есть проваленные тесты"
  exit 1
fi
```

### API scripts/lib.sh

- `compile` — компилирует `$SOURCE_FILE` (по умолчанию `Main.java`) в `.build/`. Дополнительные флаги javac передаются аргументами.
- `run_case "вход" "ожидание"` — вход через `echo` (добавляет `\n`).
- `run_case_noeol "вход" "ожидание"` — вход через `printf` (без `\n`, проверка EOF).
- `run_case_devnull "ожидание"` — пустой вход (EOF сразу).
- `run_case_args "аргументы" "вход" "ожидание"` — запуск с аргументами командной строки.
- Ожидание — точные байты. Перенос строки: `$'4\n'` (ANSI-C кавычки bash). Многострочный вывод: `$'a\nb\n'`. Без переноса: `"4"`.
- Для файловых заданий: создай временные файлы через `printf ... > f1.txt`, добавь `trap 'rm -f f1.txt f2.txt' EXIT` ПОСЛЕ `source`, подавай имя файла как вход в `run_case`.

### Проверка задания (обязательна для каждого!)

```bash
cd tasks/<раздел>/<задание>
SOURCE_FILE=Solution.java bash run_testsN_M.sh          # должно быть "Все тесты пройдены"
SOURCE_FILE=SolutionCommented.java bash run_testsN_M.sh # должно быть "Все тесты пройдены"
```

JDK определяется автоматически из `tools/jdk-*` (портативный JDK 21 уже лежит в `tools/`). Ничего устанавливать не нужно. После проверки удали `.build/` (`rm -rf .build`).

Для задач «исправь ошибки»: `Main.java` намеренно не компилируется — это нормально, не проверяй его. Для задач «напиши с нуля»: скелет `Main.java` ДОЛЖЕН компилироваться (пустой `main`), проверь: `bash run_testsN_M.sh` должен упасть на тестах (пустой вывод), но НЕ на компиляции.

## theory.md и tests.md

Смотри образец. theory.md — для новичка: что за тема, как решать, частые ошибки (таблицы). tests.md — команды `javac -encoding UTF-8 Main.java && java Main`, таблица кейсов с пояснениями, крайние случаи (пустой ввод, отрицательные числа, EOF без `\n`).

## Нумерация

Папки заданий: `01_name`, `02_name`, ... внутри раздела. Имя — snake_case на английском. Суффикс `_extra` не используется (все задания тренировочные).
